# Known limitations

- Viewports use Chromium at device scale factor 2. This is not real-device, Safari, Firefox, touch-gesture, hardware, or user-agent compatibility testing. Standalone rendering uses a desktop Chromium user agent with selected viewport dimensions; extension mode additionally sets CDP mobile metrics for phone presets.
- Preview transport is periodic raster capture with pointer, scroll, and text-field forwarding. Hover, drag and drop, pinch, arbitrary keyboard shortcuts, file dialogs, browser dialogs, popups, downloads, video, and WebGL cannot be assumed to behave as in an ordinary tab. Use the original browser tab for those workflows.
- Chrome mode reuses profile cookies/storage. Standalone mode uses one shared ephemeral browser context and does not import Chrome credentials. Cloned URLs do not reproduce the original tab's unsaved JavaScript state. There is no persistent authenticated-session import UI.
- Synchronization depends on semantic identities and visible corresponding elements. Hidden mobile navigation may require opening its menu independently. IDs are not assumed to be identical across layouts. Ambiguous controls are not guessed. Nested iframes, closed shadow DOM, custom controls, and nested scrolling need manual review. Proportional scrolling is the fallback.
- Safe-action eligibility and consequential-action detection are conservative heuristics. Arbitrary site behavior is not transactionally isolated. Do not use mirrored browser contexts as isolated purchasing or destructive-action sessions.
- Full-page capture is limited to 16 scroll steps and 16,000 CSS pixels. Font wait is at most two seconds. Infinite/lazy content, sticky elements, virtualization, and nested scrolling can create incomplete or repeated content. Capture metadata records limits and truncation. Scroll preparation may change page state despite restoring the original scroll position.
- Masking relies on known sensitive controls and user-provided CSS selectors. It cannot discover every secret inside images, canvas, custom fields, or cross-origin content. Common credential query keys are redacted; secret path segments and arbitrary query names cannot be automatically identified. Review evidence before external sharing.
- Lighthouse was evaluated but is not integrated. No Lighthouse scores are produced. Navigation timings are uncontrolled observations of the existing load. Performance, security, SEO, and accessibility completeness require additional tooling and manual review.
- axe-core findings are capped at 20 elements per violated rule. Incomplete checks are summarized for manual verification. Complex shadow/frame selectors may lack capture-time bounds; such findings retain a screenshot reference and locator but may have no focused crop.
- Codex and Miro code paths use supported real interfaces. Live AI and board exports require user authentication and tokens; automated tests exercise schemas/argument construction and stub only the external Miro transport. No live AI charge or external board modification is performed during baseline validation.
- Codex uses current CLI flags. Older CLI releases may fail with a compatibility error. Native messages larger than 950 KB are rejected explicitly; very large reports remain available in the local web workspace and output folder.
- Miro has upload and board-object limits. Unknown create-request outcomes require manual ledger reconciliation before retry. Previously completed export objects are preserved on later retries; they are not automatically refreshed after local finding edits. Create a new run for a fresh export.
- Confluence's published Whiteboard API lacks general canvas-object creation. PDF/evidence is the fallback; it is not an editable whiteboard export.
- Native Messaging installer supports Google Chrome on macOS/Linux only and requires a fixed checkout/Node location. Windows supports standalone mode. Other Chromium distributions need manual host registration. Chrome Web Store publication, signing, packaged installers, automatic updates, and cloud hosting are not included.
- Profiles and device sets are browser-local. Clearing site data clears those preferences. Disk reports survive; standalone cookies are cleared on restart. Only one active audit is supported, and UI interactions are paused during it to preserve evidence.
- The workspace UI remains a large React component. Static analysis reports maintainability and interaction-pattern warnings; it has not been refactored into independently owned route/modal components. The browser/companion services are separated into focused modules. Refer to the validation record for the scope of checks that passed.
