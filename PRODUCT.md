The desktop implementation includes live responsive views, semantic synchronization with visible interruption/recovery controls, journey recording/replay and screen checkpoints, per-project persistent or temporary sessions, clear-sign-in controls, previewed data import/export with backups, and shared profiles/devices/full-page audits/findings/history/native PDF/JSON exports. No cloud deployment.
## Product Purpose
Responsive preview and evidence-based audits. Every screen. One clear picture.
## Users
Website designers, developers, and reviewers working across mobile, tablet, and desktop viewports (inferred from the supplied workflow).
## Operating Context
The desktop preview runs its own Chromium, synchronized browsing, recording/replay, and shared current-page review workflow without extension or companion setup. Audit settings and reports hide the native views; returning preserves the live page and unsaved state when the device configuration is unchanged. Device configuration changes recreate the views and reopen the page, retaining session cookies while discarding unsaved page state. The existing web/extension workflow uses local Chrome or Playwright and the companion, and retains flow recording during migration. Each project owns its browser session and local settings/flows/report registry. Temporary browser sessions clear on app exit; exported packages exclude cookies but include ordinary recorded entries and references to evidence folders, which must remain available. Optional authenticated Codex CLI analysis, page-code evidence, and Miro paths are wired into desktop; local fixtures verify AI/page-code delivery, while live desktop AI and board writes remain unverified. Files remain local; selected evidence is sent for AI analysis only when enabled. Signed release/update configuration targets gil00pita/ViewportAtlas on GitHub; local unsigned builds disable updates and no release is published.
## Capabilities and Constraints
The attached brief and subsequent user requests are the implementation specification. Never fabricate audit results, measured scores, device testing, or successful integrations. Preserve site security headers. Chromium viewport emulation is not real-device or cross-engine testing. Audit the current page or explicitly selected screens in a recorded user flow; never crawl unrecorded pages. Responsive views share authentication within a desktop project or the extension browser profile. Private fields and configured masks are excluded; consequential actions remain source-only unless an explicit session-only test origin is enabled. Supported ordinary widgets, open-shadow controls, plain contenteditable, hover, and DOM drag are implemented, with 4,000-character text bounds. Canvas, frame internals, closed-shadow controls, file uploads, and arbitrary custom gestures require independent preparation. Rapid source handoff before acknowledgment pauses synchronization. Observed p95 is displayed without a performance-target claim. The complete 23-check source, packaged and DMG-installed suites pass on macOS Apple silicon; cross-platform execution, physical IME/native pickers, broader shortcuts, SSO, clean-machine installation, signing, and real updater upgrades remain unverified.
