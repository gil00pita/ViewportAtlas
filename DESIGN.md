# Viewport Atlas visual system
The workspace is a precise inspection bench: a dark navy-green navigation rail, cool off-white canvas, white instruments, and turquoise selected states. The supplied logo anchors the rail. Product controls use a system sans serif, compact labels, generous grouping, and legible contrast. Synthetic preview content has its own warm outdoor editorial identity so the tool and inspected page are unmistakable.

Operate mode: navigation → address and synchronization → device canvas → audit settings → evidence review. At narrow widths the rail becomes a top bar, the audit panel stacks, and device previews scroll horizontally. Use 4/8px spacing, 1px cool-gray borders, 8px control radii, and a 12px panel radius. Coral indicates attention; turquoise indicates active controls; all statuses include text. Device viewport dimensions remain independent of visual zoom. Evidence and limitations stay visible across reports, history, and integrations.

Light is the default theme. The top-bar sun/moon toggle switches the whole product interface to a dark theme and persists `atlas-theme` locally. Dark mode uses navy-green canvas and elevated surfaces, pale text, turquoise selected states, and distinct warning/error surfaces; it does not recolor captured websites or exported evidence. Semantic dark tokens and component mappings live in `src/themes.css`. An extension-compatible local head script restores the saved preference before first paint.

The inline Codex report sits above the All findings filters, showing the saved summary and AI observations. Each list item has a Codex tag and four labeled fields in order: Priority (Critical, High, Medium, Low, or info), Issue, Impact, and Recommendation. Category, devices, and verification status remain supporting metadata; Review finding opens the existing evidence controls. Structured observations in live output reuse these fields. Completed, empty, failed, pending, and disabled analysis have explicit text, with a reminder that AI judgments require verification. The report follows the existing panel language: semantic surface, ink, and border tokens, a 12px radius, 24px padding, divided findings, and compact metadata. Body text uses a 72ch maximum reading width; long content wraps. Dark mode adapts metadata and failure colors. At widths of 600px or less, padding reduces to 16px and field labels stack above their values.

Live Codex output is an off-by-default audit option beneath Codex analysis. Opted-in audits open Findings and expand an inline output panel while analysis runs. Timestamped CLI entries use a bounded, keyboard-scrollable log region; scrolling back pauses following and exposes Follow output. Completed output collapses above the report and remains available from history. The log uses existing surface and text tokens in both themes and wraps long lines on mobile.

The export dialog groups Original and A4 under PDF layout using native radio inputs. Original is selected on first load and creates a single whiteboard canvas with aligned screen tops, full screenshots in their original proportions, and a separate findings column. A4 scales each complete screenshot onto one page. Preview and download share the selected layout. The controls use existing surface, border, ink, and teal tokens and stack on mobile.

Include page code is an off-by-default switch beneath Codex analysis, preceding Live Codex output. Helper text names HTML, readable CSS, and script URLs. The consent dialog conditionally explains the added code payload, omissions, and saved snapshots; changing the option resets acknowledgment. It uses the existing audit-switch layout, internal settings scrolling, and theme tokens.
